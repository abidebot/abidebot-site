The three parts

An OS, a browser and a network, all written in munu.

munu is the programming language AbideBot is written in. Your agent writes munu programs, munuOS runs them and munuScene shows them. The network that carries munu data is in development.

munuOS In development

The always-on operating system your agent lives in.

munuOS is a minimal Linux-based operating system image where munu is the first process. It runs your munu programs and your agent, always on, one per customer, never shared. Rent one hosted by us, or run it on your own hardware.

  • Your agent, its memory and its jobs live here
  • Changes go live only after they compile and pass their checks
  • A protected core that boots with only the essentials

munuScene In development

The AI-native browser: apps as scenes, not pages.

munuScene draws munu apps from scenes instead of rendering web pages. A scene is plain data, so your agent is designed to use apps directly, as a first-class user: it reads the scene and binds the variables the app is waiting on, where other agents take screenshots and guess.

  • It does not render ordinary HTML websites
  • You and your agent see the same app
  • Risky steps wait for your approval

The network In development

Everything as live, shared data.

Documents, sites and apps are designed to be ψ-terms: shared structures that each party fills in, with a conflict caught instead of overwritten. The routing and the encrypted frames that carry them are built and tested between running nodes. Linking munuOS machines on it is still ahead.

  • Routed by hyperbolic coordinates, no central directory
  • Every message travels in a fixed-size encrypted BlackFrame
  • Planned: every bot reachable by its QR code
Why it’s different

Built for an agent that does the work itself.

Most AI agents are bolted onto software made for people. AbideBot is designed the other way round.

It uses apps directly Designed for

An app in munuScene is a scene: a tree of values the agent can read. It is designed to read exactly what is on screen and fill in the value a control is waiting for, by name, with no screenshots, no pixel guessing and no scraping. That is also designed to need far fewer AI calls than reading images, though we will publish benchmarks before we claim savings.

It stays on Designed for

munuOS is designed to run all the time, so routines, watches and replies keep going when your laptop is shut. When a part fails, munuOS restarts it by the rule written in its code, and a bad change rolls back to the last good one.

Its code is checked before it runs

Dude writes small munu programs for your tasks. The compiler rejects a missing case, a recovery rule for a failure that can never happen, or two parts that disagree about a value’s type, and the error goes back to the agent to fix. See the real code →

Rules and deadlines live in the code

How each part recovers, how fast it must answer and where order may vary are written in the program itself, as formulas the compiler turns into checks. munuOS is designed to measure every run against its deadline and report a miss, not hide it.

Meet Dude

Your agent is called Dude. Rename it if you like.

Every new agent starts out as Dude. Call yours anything you like. Whatever its name, it writes real munu programs for your tasks, and checks them before they go live.

  • You don’t need to learn munu. Ask in plain words. Dude writes the program, compiles it on your munuOS machine and fixes what the compiler reports.
  • Calls the AI only when it needs judgement. The routine runs as checked code, so the model is not asked about every step.
  • Approvals only a human can give. Risky steps pause until you approve them. The agent cannot answer for you.
  • A factory reset that always works. A protected core can boot with only the essentials, so a bad change can never lock you out.

FAQ

Questions, answered calmly

What is munu?

munu is the programming language AbideBot is written in. Programs are made of finite functions (mu) and ongoing streams (nu), grouped into contracts that state their own recovery rules and deadlines. munuOS runs munu programs, munuScene draws munu apps, and the network is designed to carry munu data. More for developers →

Do I need to learn munu to use AbideBot?

No. You ask Dude in plain words and it writes the munu. Learning munu is for people who want to build their own apps for the network.

Is munuScene a web browser?

No. munuScene is a browser for munu apps, and it does not render ordinary HTML websites. It is designed for munu apps and sites, drawn from a scene graph your agent can read and act on directly.

Do I host munuOS myself, or rent it?

Either. You are planned to be able to run munuOS free on your own hardware, or rent a machine running it, hosted by us on a monthly plan. Both run the same munuOS image. Firms that host it themselves can add paid support. Self-hosting is planned, and the code is not public yet. Join the waitlist and we will tell you when it is.

Is my munuOS machine shared with other customers?

No. Each customer gets a separate virtual machine running munuOS. Customers never share a machine or its core.

Is there an uptime SLA?

Not yet. The Team node is designed for a 99.5% uptime target, shown on a public status page, with no service credits. A monthly SLA with service credits is planned for the Business SLA node, which is coming later.

Can agents see all my files?

No. They can read and write only what you grant, and you can revoke a grant at any time. Code written by the AI never runs on your own computer with your computer’s permissions.

How is AI usage billed?

Through a prepaid balance that you top up by hand or automatically. It is charged at the model provider’s cost plus a small disclosed markup. When the balance reaches zero, the AI stops. Nothing is billed after the fact.

Why is my agent called Dude?

It is the default name. Rename it whenever you like.
