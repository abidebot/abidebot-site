Why abidebot

Built on a foundation designed for AI agents

Most assistants are chat apps with a server bolted on. abidebot runs on our own purpose-built runtime, made from the ground up so an AI can do real work safely.

Your own private cloud computer

Every customer gets a separate virtual machine. Customers never share a machine or its core, so your work stays isolated from everyone else's.

Always on, 24/7

Your routines keep running after your laptop sleeps or you close the app. Results wait for you when you come back.

Locked down by design

The cloud computer runs our software and nothing else. There is no shell and no way for it to start other programs, so there is far less for an attacker to use.

Approvals only you can give

When a step needs your yes, abidebot pauses and waits. Only you can fill an approval. The assistant cannot answer it for you.

File access you grant, folder by folder

abidebot reads and writes only the folders you grant. Revoke a grant and the work that depended on it stops at once.

A spending limit it cannot override

Your budget is held in a protected core that the assistant cannot change. It can improve itself, but never its own limits.

Safe self-improvement

It writes real programs, then proves they work before they stick.

abidebot does not just chat. It writes programs for your tasks and compiles them on your cloud computer. Errors go straight back to the assistant, and it fixes them on its next turn.

  • Probation, then commit. A new version runs under supervision first. If it crashes, the previous version returns automatically.
  • Factory reset that always works. A protected core can boot with only the essentials, so a bad change can never lock you out.
  • No silent mistakes. Every failure carries its cause, and numbers never silently overflow: a calculation fits or it stops with a clear reason.
  • Nothing hidden. When a step is refused, the assistant sees the true state and the reason, and corrects course.

How it works

Three parts, one shared memory

A native desktop app, a private cloud computer, and one store of facts that both of them share.

Choose where it runs

On first launch, pick hosted (we run your cloud computer), your own server, or local only on your own machine. There is no hidden default.

Ask in plain language

Talk to your assistant in rooms and threads in the desktop app. It shows when it is working and when it is waiting for you.

It builds and runs the job

The assistant writes a routine with time or event triggers. The routine runs as checked code and calls the AI only when it needs judgement.

Results sync everywhere

Results land in one shared store. Open the app on any device and you see them. Only changes travel, not whole documents.

FAQ

Questions, answered

What is abidebot?

abidebot is an AI assistant with a desktop app and its own private cloud computer. You ask for something in plain language, and it writes and runs the routines that get it done, even while your own computer is off.

Is my cloud computer shared with other customers?

No. Each paying customer gets a separate virtual machine. Customers never share a machine or its core.

Can abidebot see all the files on my computer?

No. It can read and write only inside the folders you grant, one at a time. When you grant a folder to a hosted cloud computer, the app tells you that the files go to that server and to the AI model provider. You can revoke a grant at any time. Code written by the AI never runs on your own machine with your machine's permissions.

What stops it from running up a bill?

Your spending limit lives in a protected core that the assistant cannot modify. The assistant can rewrite its own routines, but not the core that holds your budget, your keys and the safety checks.

Can I run it on my own server?

That is the plan. The same image we host will run on your own server or your own machine with one launcher, on both x86_64 and arm64. On first launch you choose hosted, your own server, or local only.

How do I know my cloud computer runs what you say it runs?

Our image build is reproducible. The app shows the fingerprint (hash) of the image on your cloud computer, and you can compare it with the fingerprint of the public release.

What happens when my cloud computer is idle?

An idle cloud computer sleeps from a snapshot and wakes before its next scheduled routine, so your jobs still run on time.
